## 一、Mock 数据排查：通过 ✅

**结论：不存在硬编码模拟 AI 功能的情况。**

所有"AI 输出"均通过 `server/llm.py` 发起真实 HTTP 调用（OpenAI / Anthropic 双协议），无任何预设文案冒充生成结果：

| 功能 | 真实调用点 |
|---|---|
| 开场问候 / 晨报 | `main.py:120` / `main.py:177` |
| 意图分类 | `router.py:30` → `complete_json` |
| 闲聊流式回复 | `main.py:319,327` → `llm.stream` |
| DAG 规划 | `planner.py:65` |
| 节点执行（llm 工具） | `executor.py:15` |
| 卡片合成（含保底直出） | `synth.py:31,49` |
| 记忆抽取沉淀 | `memory.py:229,245` |
| 传话筒翻译 | `main.py:533` |

每次调用留痕 `data/logs/llm_calls.jsonl`，`GET /api/logs` 可供评委验真。

### 降级路径均为诚实降级，不伪造 AI

- `router._fallback`（`router.py:15`）：LLM 挂了只做关键词**路由**，不伪造内容，`reason` 标记"关键词保底"
- `/api/briefing` 兜底（`main.py:189-193`）：输出基于本地数据的实话，打印降级日志
- `synth.direct_card`：DAG 失败后的保底仍是真实 LLM 直出，非模板填充
- 节点失败 → 注入"（本环节查询失败…）"标记后照常进合成
- `web_search` 无 Key → 降级为真实 LLM 节点（`executor.py:45-46`）
- 前端成长雷达 404 → 明示"功能开发中"，本地估算标注"非服务端评估"（`app.js:1846-1873`）
- `index.html:16` 注释明确声明容器"不放任何假数据"

### data/ 定性

- `race_db.json` / `transport_db.json`：**工具的本地数据源**（`race_lookup`/`transport_lookup` 是规划器可调的真实工具），交通库自带"以 12306 为准"免责声明并透传到输出
- `data/child_xiaodou/`：预置演示档案，README 第 38 行已公开声明，属种子数据非运行时伪造

## 二、真实功能缺陷（演示中可见，建议修复）

### P0-1 `GET /api/checklist/{cid}` 端点缺失 → 清单功能断链 ✅已修

- `app.js:697` `checklistBlock` 会 GET 此端点，但 `main.py` 只注册了 `POST /api/checklist/{cid}`
- 预置档案 `xikesong.checklist_id=xikesong_pack` 永远走 GET → 404 → 事务详情里永远显示"清单暂时取不到"，9 项预置清单无法展示、勾选入口不可达
- 根源：该端点存在于早期 `接口契约-v6.md:192`，最终 `契约-v6.md §4` 删掉了，前端未同步
- **修法**：在 `main.py` 补一个 GET 端点，调 `AffairStore.checklist(cid)` 返回 `{"checklist": ...}`

### P0-2 `relay_result` SSE 事件前端无处理 → 聊天内传话筒结果被吞 ✅已修

- `main.py:280` relay 意图发 `{"type":"relay_result", ...}`，`app.js:1199` 的 switch 无此 case → 只亮"传话筒"徽标，翻译结果从不上屏
- 叠加问题：家长视图 `#relay-btn` 固定 `teacher2parent`，`child2teacher` 仅能经聊天触发 → 孩子→老师方向端到端失效
- **修法**：`handleEvent` 加 `case "relay_result"`，把 `message`/`advice` 渲染成一条 ai 消息（或沿用卡片样式）

### P0-3 `main.py:153` 字段名错误：`days_left` 不存在 ✅已修

- `due_soon()` 返回键为 `days`（`affairs.py:358`），晨报 prompt 读 `d.get('days_left')` → LLM 输入里是"还有 None 天"
- **修法**：`days_left` → `days`

### P1-4 `llm.stream` 无备用 Key 切换 ✅已修

- `complete()` 遍历主备 Key（`llm.py:106`），`stream()` 只用 `_keys()[0]` 不重试（`llm.py:149`）→ 最高频的闲聊通道没有 README 宣称的"主备 Key 自动切换"
- **修法**：`stream` 外层套与 `complete` 相同的逐 Key 尝试循环

### P1-5 `POST /api/affairs` 契约字段不符 ✅已修

- 契约：`{name, id?, patch?}`；实现读 `req.data`（`main.py:59,471`）→ 按契约发 `patch` 静默忽略，更新不生效
- 当前无调用方，属潜伏缺陷
- **修法**：`AffairReq` 增加 `patch` 字段兼容，或直接改契约为 `data`

## 四、小瑕疵（记录，可不修）

- `_execute_actions` 的 `parent_confirm` 触发词含"去"（`main.py:409`），"我想去学钢琴"也会塞家长收件箱
- `actions._time_value` 认不出 "10/17" 这类日期 → 静默退化为"每天"提醒（`actions.py:62-65`）
- `scene3d.js:2259` `spawnMemory` 给新节点硬编码 `private:false`，memory 事件载荷也不带 private 字段 → 悄悄话节点在 `loadGraph()` 刷新前短暂可见（家长视角同理）
- `GET /api/graph` 的 `view` 不校验：任何非 "parent" 值都返回含 private 的完整图
- 左栏"临近截止"文案"近 7 天"，后端窗口实为 30 天（`main.py:152`）
- 前端读了一批后端永不返回的字段：`data.findings`、`data.relay`、`item.options`、`card.checklist`、`card.footnotes`、`due_in_days`——无害死代码，但掩盖了 P0-1
- 会话历史仅存内存，"刷新恢复"覆盖页面刷新但服务重启即丢
- `_open_affair` 去重靠 `title[:6] in message`（`main.py:375`），换种说法会重复建事务

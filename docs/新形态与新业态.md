# 新形态与新业态（2026-10-03）

> 定位不变：**管家是教育行业的服务层，不是内容层**——不做任何一节课，只管课外的"办"。
> 本文回答两个问题：管家还能**以什么形态**出现在孩子身边？还能**靠什么业态**赚钱？
> 标 ✅ 的已在仓库落地、可现场演示；标 🗺 的是 roadmap 话术，不承诺已实现。

---

## 一、新形态：管家住在哪里

| 形态 | 解决什么 | 状态 |
|---|---|---|
| **网页 → 桌面 APP（PWA）** | 手机"添加到主屏幕"即全屏独立窗口，像 APP 一样打开；零安装、零审核、跨 iOS/Android | ✅ `web/manifest.webmanifest` + `web/sw.js` |
| **断网可翻的档案** | 断网时记忆本/事务/星球用上次的数据撑起来；**AI 端点不缓存**，断网就如实停答——恰好证明回复是实时生成的 | ✅ SW 网络优先策略，缓存键按 token 隔离（家长缓存拿不到孩子视角） |
| **家长侧的"一页纸"** | 家长不想刷聊天记录，只想每周看一页：进展、留意、周末做什么、怎么夸孩子 | ✅ 家长视图「本周成长周报」 |
| **IM 渠道（微信/企微/飞书机器人）** | 家长不装任何东西，周报与"请确认"直接推到家庭群；家长回"好"即审批 | 🗺 周报/收件箱接口已就绪，只差渠道适配层 |
| **家庭共享屏 / 儿童手表** | 极简视图：一句晨报 + 今天 3 件事 + 一个语音键；复用 `/api/briefing` | 🗺 |
| **实体熊猫玩偶（音箱）** | 低龄、无屏幕的孩子；记忆仍在云端/家庭服务器，玩偶只是"嘴和耳朵" | 🗺 |

**口径**：形态会变，管家不变——同一份记忆档案，换个壳出现在孩子的不同年龄段。

## 二、新业态：钱从哪里来

原三层付费方（2C 家长订阅 / B2B2C 教培采购 / 2G 公益）不变，新增三个抓手：

### 1. 学校/机构：「一份通知，千家千版」✅（B2B 的演示证据）

- **场景**：老师在群里发"周五秋游，自带午餐"。现在每家都要自己读、自己记、自己准备，老师还要回答几十遍"几点集合"。
- **管家做法**：通知粘进来（或机构账号批量下发），管家**按每个孩子的记忆**出专属版——小豆家的版本会写"感冒还没好，记得带药"——并**自动建事务 + 清单 + 提醒**，落进看板。
- **实现**：`POST /api/notice`；家长单家落地，admin（代表机构账号）带 `names` 批量下发，并发 4、单家失败不拖累其它家；同一通知重复粘贴认领旧事务不重复建单；prompt 只读图谱层，悄悄话结构性不可达。
- **ROI 公式**（数字需团队核实后才能上 PPT）：
  ```
  年节省/岗 = 班级家庭数 × 每条通知的答疑工时 × 每周通知数 × 节省比例 × 52 × 时薪
  示例假设：40 户 × 3 分钟 × 3 条 × 60% × 52 × 50 元 ≈ 3.7 万元/班/年
  ```
- **评委口径**："家校沟通的人力不是耗在发通知，是耗在通知之后的一对一翻译和答疑——这一段管家全接了。"

### 2. 服务撮合：家长收件箱就是交易入口 🗺

- 管家已经在做的事：拆解需求 → 准备方案 → **推给家长确认**（车票、报名、费用）。
- 下一步：确认卡片上挂真实服务方（车票、夏令营、赛事报名、陪诊、托管），家长一键确认，平台抽佣。
- 红线：**管家只推荐不代付**；推荐必须标"参考信息，以官方为准"；记忆数据绝不用于广告定向（隐私即护城河）。

### 3. 成长档案：从童年备忘录到升学材料 ✅/🗺

- ✅ **童年备忘录导出**：记忆本页一键打包整份档案（markdown + json + README），`GET /api/export`。只交还给孩子本人——里面有悄悄话，家长账号 403。
  口径："数据即文件，没有藏在别处的副本；孩子长大后带走的是一本童年备忘录，不是被锁在平台里的账号。"
- 🗺 **综评/升学素材**：图谱 + 代办文书 → 综合素质评价材料、竞赛履历、自荐信初稿；按次付费或会员权益。

### 4. 2G：留守儿童「远方父母周报」✅（复用家长周报）

- 留守家庭的父母最缺的不是视频通话，是"这周孩子到底怎么样"。家长周报就是那一页纸：进展、身体/情绪苗头、一条能远程做的小事、一句可以当面夸孩子的话。
- 政府/公益采购按户计费，周报可经 IM 渠道推送（🗺）。

## 三、本轮落地清单（可现场演示）

| 功能 | 演示步骤 | 文件 |
|---|---|---|
| 家长周报 | 豆豆妈登录 → 家长视图 → 「生成周报」 | `server/family.py` `GET /api/parent/weekly` · `prompts.WEEKLY` |
| 通知落地 | 家长视图 → 传话筒 → 「学校通知 → 落成待办」→ 粘通知 → 看板出现新事务 + 清单 | `POST /api/notice` · `prompts.NOTICE` |
| 机构批量下发 | admin 调 `POST /api/notice {names:[...]}` | 同上 |
| 童年备忘录 | 孩子登录 → 记忆本 → 「导出童年备忘录」 | `GET /api/export` |
| PWA | 手机浏览器打开 → 添加到主屏幕；断网后重开仍能翻记忆本 | `web/sw.js` `web/manifest.webmanifest` |

**隐私边界（三个新功能一致）**：周报与通知的产出会给家长看，记忆只取图谱层（`brief_block`/`recall` 在构造上剔除 private 节点），本周统计也先滤 private，仅报"另有 N 条悄悄话，未计入"；导出只给孩子。`tests/test_family.py` 对这三条断言（悄悄话原文不进任何周报/通知 prompt）。

**降级不降真**：周报 LLM 不可用 → 只用统计数据说实话（`llm: false`，前端标注）；通知落地失败 → 如实报错，不伪造落地结果。

## 四、评委问答补充

| 问题 | 口径 |
|---|---|
| 学校为什么愿意用？ | 不改变老师的工作方式——老师照样发通知，管家在家庭这一端把通知"落地"，答疑量下降就是学校看得见的收益 |
| 和钉钉家校/晓黑板有什么不同？ | 它们解决"通知送到"，管家解决"通知之后"：每家的专属版、要带的东西、谁该做什么、到期提醒——而且知道这个孩子感冒还没好 |
| 家长周报会不会变成监控？ | 周报只来自事务和图谱的公开层，悄悄话只计数不显示；管家受雇于家长、服务于孩子，边界是规则不是承诺 |
| 做 APP 吗？ | 已是 PWA，可装桌面、断网可翻；原生 APP/手表/玩偶是同一份档案换个壳，不是另起炉灶 |
| 怎么赚钱？ | 2C 订阅（周报是核心卖点）+ B2B 机构按班/按户（通知落地）+ 撮合佣金（收件箱）+ 2G 留守周报 |

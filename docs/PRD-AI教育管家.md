## 0. 设计原则

1. **可行性压倒一切**：每项 P0 都标了工作量与保底方案，任何环节翻车都有降级路径，保证 10/3 晚一定有可跑的成品。
2. **一切为 5 分钟路演服务**：先定剧本（第 4 节）再反推功能；演不出来的不进 P0。
3. **诚实即防线**：AI 输出全部实时生成；演示档案是预置"用户数据"；roadmap 明说。原创性无瑕疵——仓库代码全部比赛期新写，OpenPanda 仅作设计参考并在 README 声明。
4. **降级不降真**：保底路径只砍展示层（任务树→顺序日志、DAG→直出卡片），**绝不跳过 LLM 实时生成**——"固定模板填充"不做，撞"硬编码答案"红线。

## 1. 问题定义（路演开场 30 秒）

1. **三方沟通断层（对应真实部门场景）**：辅导班老师的专业话家长听不懂；孩子的心里话对谁都说不出口。落在企业侧：**学校的家校共育/德育处、教培机构的学员服务与教务部门**，每天大量人力耗在"学情翻译"和家校沟通上——缺"翻译器 + 传声筒"。
2. **孩子没人做通盘规划**：真实案例——有家庭花 8 万/月请人当孩子的"管家"（教学另有老师，管家管沟通、连接、安排）。绝大多数家庭请不起，需求却是普遍的。
3. **通用 AI 接不住**：豆包面向所有人全行业、被动应答、记忆浅。不知道你两年前钢琴没坚持，不会把"最近攒钱"和"想换电脑"联系起来，不会因为你感冒就提醒带药。

> **孩子缺一个"认识他很多年、替他通盘考虑"的角色。真人管家是奢侈品，通用 AI 不认识孩子。**
>
> **行业定位口径**（评委问"哪个行业哪个部门"的标准答案）：教育行业 · **家校协同与学员成长服务环节**——学校德育处/家校沟通岗、教培机构教务与学员服务部门。

## 2. 产品形态与边界

网页应用（手机宽度适配）：进入页登录选档（输名字绑定孩子档案，评委各玩各的互不干扰）；主屏上半熊猫形象（SVG/CSS 动画：眨眼、浮动、表情切换、点击互动），下半对话框 + 建议问题 chips，侧页"记忆本"。

| 做 | 不做（roadmap 或砍掉） |
|---|---|
| Web 单页：登录选档 + 形象 + 对话 + 任务树 + 记忆本 | APP/手表/电子宠物 |
| 事件驱动的任务拆解与执行 | 真实订票/支付（无接口，roadmap 讲虚拟机代操作+企业合作） |
| 文件式记忆读写 + 翻看（写入加锁原子写） | 摄像头/GPS 采集 |
| 结构化卡片/图谱输出 | 家长/老师独立后台 |
| 开场主动问候（记忆驱动生成） | 后台常驻主动触发（roadmap）；婴幼儿段；记忆变现（隐私红线） |

## 3. 系统架构（自研精简版，估计核心 ~900 行）

```
┌─ 浏览器单页（比赛期原创）──────────────────────────┐
│ 登录选档 │ 熊猫形象区 │ 对话框+建议chips │ 任务树 │ 记忆本 │
│ POST /api/session   POST /api/chat                 │
│ GET /api/greeting   GET /api/memory                │
│ GET /api/plan/{id}/events (SSE 节点状态流)          │
└──────────────────────┬────────────────────────────┘
┌─ PandaButler Server（FastAPI，比赛期原创）──────────┐
│ session  ：登录名 → 绑定 data/{child}/ 档案目录      │
│ router   ：LLM 分类 → 闲聊直答 | 事件→出计划         │
│ planner  ：LLM 输出 JSON DAG {nodes, depends_on}    │
│ executor ：按依赖并行/串行执行节点 → SSE 推状态      │
│ synth    ：汇总节点结果 → 结构化卡片                 │
│ memory   ：每轮后 LLM 抽取 → 写 memory/ 文件         │
│          ：每轮前 注入"活跃关注点"+检索相关 topic    │
│          ：写入走单写锁 + tmp→rename 原子替换        │
│ tools    ：赛事知识库 │ web_search │ 天气(wttr.in)   │
│ LLM      ：OpenAI 兼容（BASE_URL/API_KEY 走 env）   │
└────────────────────────────────────────────────────┘
存储 = 文件系统（data/{child}/：memory/*.md + index.json + reminders.json），不装数据库
```

### 3.1 技术选型（按可行性排序）

| 件 | 首选 | 保底 |
|---|---|---|
| 后端 | Python FastAPI + asyncio（SSE 用 StreamingResponse） | Node Express |
| 前端 | Vite + React 单页 | 纯 HTML+JS+CSS 单文件（连构建都不要） |
| 熊猫形象 | SVG + CSS 动画（眨眼/呼吸浮动/表情 class 切换） | 一张静态 PNG + CSS 浮动 |
| 任务树 | DOM 列表 + 缩进 + 状态色动画 | 顺序日志流式渲染 |
| LLM | DeepSeek/Kimi/Qwen 任一 OpenAI 兼容 API | 双 Key 互为备份 |
| 记忆 | markdown 文件 + index.json（参考 panda memory/ 格式） | 单文件 JSONL |
| 会话 | 登录名 → data/{child}/ 目录绑定 | 全员共用小豆档（写入仍加锁） |
| 部署 | 自有云服务器 + uvicorn + nginx/端口直出 | 仅 localhost 演示 |

## 6. 记忆与数据设计

```
data/child_xiaodou/
  MEMORY.md            # 长期记忆：性格/兴趣/重要计划
  topics/钢琴.md        # status: dropped, related: 兴趣班,乐器
  topics/换电脑.md      # status: active, related: 攒钱
  topics/西客松.md      # 赛事：10/18·西安·赛道（与赛事库 json 一致，晚于演示日）
  daily/2026-09-XX.md   # 每日对话沉淀（样例若干）
  index.json           # {topic: {type,status,related[],file}} 检索索引
  reminders.json       # P1：[{text, time, fired}]
data/race_db.json      # 赛事知识库：西客松=10/18 西安等，工具查询数据源
```

- **注入策略**（抄 panda injector 思路）：每轮 prompt = 人设 + "活跃关注点块"（active 项全量，实现"一直知道"而非临时检索）+ 相关 topic 检索（index.json 关键词/LLM 选取）+ 历史尾部。
- **写入策略**：每轮对话后一次抽取调用写 daily；关键事实 upsert topics/MEMORY。演示档案 ≤10 条，每条剧本可引用。
- **并发**：评委可能同时操作——所有文件写入走单写锁 + tmp→rename 原子替换；会话按登录名绑定 `data/{child}/`，档案互不污染。登录名无匹配档案时落到共用演示档（小豆）或空白档，二选一拍板。
- **隐私叙事**：数据即文件、自部署即私有——"孩子数据不出自家服务器"。云端实例是演示部署，产品形态支持家庭私有化。

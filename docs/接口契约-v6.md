## 1. 数据文件

### 1.1 `data/child_xiaodou/graph.json`（成长图谱）

```json
{
  "nodes": [{
    "id": "piano",
    "label": "钢琴",
    "domain": "美",             // 德|智|体|美|劳（五领域，用于分星区与配色）
    "type": "interest",         // interest|event|goal|health|person|trait|place|thing
    "status": "active",         // active|dropped|done
    "first_seen": "2024-03",    // YYYY-MM 或 YYYY-MM-DD
    "last_seen": "2026-10-02",
    "weight": 3,                // 提到次数，决定节点大小
    "private": false,           // true=悄悄话，家长视角不可见
    "facts": [{"date": "2024-03", "text": "学了三个月，坐不住放弃了"}]
  }],
  "edges": [{"source": "save_money", "target": "new_pc", "rel": "为了", "since": "2026-09-30"}]
}
```
- 读取：`{"nodes": [...], "edges": [...]}`；缺失文件返回空结构，不要抛错。
- 家长视角过滤：`private: true` 的节点及其相连边整体移除。
- 写入：与 markdown 记忆同样走**单写锁 + tmp→rename 原子写**。

### 1.2 `data/child_xiaodou/affairs.json`（事务）

```json
{
  "affairs": [{
    "id": "xikesong",
    "title": "西安西客松参赛",
    "emoji": "🏆",
    "kind": "trip",              // trip|goal|health|decision|study|other
    "stage": "executing",        // discovered|planning|executing|awaiting_parent|following|done
    "due": "2026-10-18",         // 可空
    "owner_next": "butler",      // butler|child|parent
    "progress": null,            // goal 类用 0~1（如换电脑 0.62）
    "progress_text": null,       // 如 "已攒 6200/10000 元"
    "linked_nodes": ["xikesong", "cold", "robot_class", "xian"],
    "summary": "一句话当前状态，看板上展示",
    "checklist_id": "xikesong",  // 指向 checklists.json，可空
    "created": "2026-09-30",
    "log": [{"ts": "2026-09-30 20:10", "actor": "child", "text": "报了西客松大赛"}]
  }]

```

## 2. 后端

### 2.1 模块结构（`server/`）

| 文件 | 职责 |
|---|---|
| `graph.py` | **新**。GraphStore：读/写 graph.json、原子写、单写锁、家长视角过滤、按领域分组、时间轴切片（`snapshot(until="2025-01")`）、节点 upsert 与按标签归一合并 |
| `affairs.py` | **新**。AffairStore：读/写、状态机流转、加日志、清单读写、进度更新、按 stage 分组、`due_in_days` 计算 |
| `briefing.py` | **新**。巡检结算 + 晨报生成：扫描事务的截止日/停滞、扫描 race_db 未来 60 天的赛事（发现新事务候选）、生成晨报文本（LLM 流式或整段） |
| `relay.py` | **新**。传话筒：`teacher2parent`（老师原话 → 家长版 + 孩子版）、`child2teacher`（孩子心里话 → 给老师的得体消息） |
| `actions.py` | **新**。执行动作：`add_reminder` / `make_checklist` / `ask_parent` / `export_ics`，返回统一的 `{kind, label, payload}` |
| `llm.py` | 修 B1（见 2.5）；`caller` 参数保留 |
| `router.py` | 意图扩为 `chat | new_affair | affair_update | relay`，同时返回 mood |
| `planner.py` | DAG 校验后**计算 layer**（同层可并行），供前端分层布局；工具集加入新工具 |
| `executor.py` | 支持"动作节点"（`tool` 为动作名时调用 actions） |
| `synth.py` | 卡片支持 `footnotes`（记忆引用） |
| `memory.py` | 抽取结果升级为节点/边/事务（见 2.3）；对话归档写入 |
| `tools.py` | 新增 `transport_lookup`；`race_lookup` 增加"列出未来 N 天赛事"能力 |
| `main.py` | 新增端点（2.6）+ SSE 事件（2.4） |

### 2.2 检索与 recall

`retrieve(query)` 改为结构化：
```python
{"nodes": [{"id","label","score","via": None|"为了"}],
 "edges": [["save_money","new_pc"]],
 "text": "注入 prompt 的文本"}
```
算法：bigram 命中节点标签/related → 得分；再沿边扩一跳（"攒钱"命中 → 带出"换电脑"及关系）；活跃(active)节点不去重，因为 recall 要显示"想起了什么"。命中结果同时①注入 prompt ②推 `recall` 事件。

### 2.3 抽取升级（`memory.py`）

`EXTRACT` 输出：
```json
{"daily": "一两句话",
 "upserts": [{"node": "钢琴", "domain": "美", "type": "interest", "status": "active", "fact": "又说想学钢琴"}],
 "edges": [{"source": "钢琴", "rel": "联想到", "target": "小提琴"}],
 "affairs": [{"action": "create|update", "id": "xikesong", "patch": {"stage": "executing"}}],
 "longterm": "", "emotion": "开心", "private": false}
```
写入顺序：daily → graph（upsert 节点/边）→ affairs → MEMORY.md，全部原子写，然后推 `memory` 事件。失败静默，只少一个提示。

### 2.4 SSE 事件（`POST /api/chat`，逐条完整定义）

```
{"type":"mode","mode":"chat|plan|affair|relay","mood":"normal|happy|sad|nervous"}
{"type":"recall","nodes":[{"id":"cold","label":"感冒","score":6,"via":null}],"edges":[["save_money","new_pc"]]}
{"type":"token","text":"…"}
{"type":"affair","action":"created|updated","affair":{…完整事务对象…}}
{"type":"plan","title":"…","nodes":[{"id":"n1","title":"查赛事","tool":"race_lookup","depends_on":[],"layer":0}]}
{"type":"node","id":"n1","title":"查赛事","status":"running|done|error","tool":"race_lookup","args":{"query":"西客松"},"detail":"命中 1 条"}
{"type":"action","kind":"reminder|checklist|parent_confirm|ics","label":"已加 3 条提醒","payload":{…}}
{"type":"card","card":{"title","emoji","sections":[{"heading","items":[]}],"closing","footnotes":[{"text":"因为你感冒还没好","node_id":"cold"}]}}
{"type":"memory","added_nodes":[{"id","label","domain","type","status"}],"added_edges":[{"source","target","rel"}],"daily":"…"}
{"type":"done"}
{"type":"error","message":"…"}
```
顺序保证：`mode` → `recall` → (`token`*) 或 (`affair`/`plan`/`node`*/`action`*/`card`) → `memory` → `done`。
`memory` 必须在回复正文显示之后再推（抽取在正文之后执行）。

## 3. 前端

### 3.1 结构与模块

```
web/index.html      单页：HUD 布局 + 三个视角容器
web/style.css       夜色竹林主题 + 毛玻璃 HUD
web/scene3d.js      零依赖软件 3D 渲染器（透视投影 + 画家排序 + 平面着色 + 相机动画）
web/planet.js       记忆星球：五领域星区 + 力导向 + 节点/边 + 时间轴 + 拾取
web/panda3d.js      低多边形熊猫管家（基础几何拼装 + idle/thinking/working/happy/worried 状态）
web/app.js          状态管理、SSE 处理、各面板渲染
web/api.js          fetch 封装
```

### 3.2 3D 渲染器规格（`scene3d.js`，禁止外部依赖）

- 场景图：`Mesh{verts, faces(索引, 颜色), transform}`；相机：轨道式 `{target, theta, phi, dist}`。
- 每帧：顶点 → 模型/相机变换 → 透视投影 → 面按深度排序 → 填充 + 单方向光平面着色。
- 需要的能力：`addMesh/removeMesh`、`setCamera`、`flyTo(target, dist, ms)`、`pick(x,y)`（把屏幕坐标反查最近节点）、`glow`（径向渐变光晕）、`particles`（沿边流动粒子）。
- 性能目标：≤80 个节点、≤120 条边时，投屏笔记本 60fps；否则自动降到 30fps 并减少粒子。
- `prefers-reduced-motion` 时关闭粒子与自动旋转。
- 若 `canvas.getContext("2d")` 不可用（极罕见），显示 2D 列表降级（`app.js` 负责）。

### 3.3 记忆星球（`planet.js`）

- 五个星区按 `domain` 分布（域心 + 域内力导向），节点半径 = `f(weight)`，亮度 = 新近度（`last_seen` 距今天数），`status=dropped` 为灰虚影，`done` 带金环，`private` 在家长视角整体隐藏。
- 边为细线 + 关系文字（字号随距离缩小到 0）。hover 节点高亮其一跳邻居，其他变暗。
- 点击节点：`flyTo` + 右侧/下方抽屉显示 label、域、状态、时间线与关联节点。
- 时间轴：滑块 + ▶ 播放；按 `first_seen` 出现/隐藏节点；播放时节点依次点亮。
- 对外 API：`init(canvas, data)`、`setData(graph)`、`flash(nodes, edges)`（recall）、`grow(newNodes, newEdges)`（memory）、`highlightDomains([...])`、`snapshot(until)`、`pickAt(x,y)`。

### 3.4 视角与布局

三个视角：`child`（孩子端）/ `parent`（家长端）/ `board`（事务看板，可全屏）。

**宽屏 ≥1100px**：三栏 —— 左栏 340px（晨报 + 事务看板）、中栏自适应（3D 场景 + 星球 + 时间轴）、右栏 380px（对话流 + chips + 输入）。顶栏含视角切换、日期、健康状态。
**手机 <768px**：单栏 + 底部 Tab（管家 / 星球 / 事务 / 对话）；3D 保留但节点数减半。

家长视角：`body[data-view="parent"]` 切白天配色，左栏换成待确认收件箱，右栏换成传话筒（左输入右双栏输出），顶栏显示"🤫 小豆有 N 条悄悄话，管家替他保密"。

### 3.5 视觉规范

| 项 | 值 |
|---|---|
| 背景 | 径向渐变 `#0f1a1f` → `#1c2b2a` |
| 主色 / 强调 | 竹青 `#4fbf7f` / 暖橙 `#ffb347`（仅倒计时与行动按钮） |
| 五领域 | 德 `#ff8a80` · 智 `#64b5f6` · 体 `#81c784` · 美 `#ce93d8` · 劳 `#ffd54f` |
| 面板 | `rgba(18,28,30,.62)` + `backdrop-filter: blur(14px)`、1px `rgba(255,255,255,.08)`、圆角 18 |
| 白天（家长） | 背景 `#f2f6f4`、面板白、文字 `#1d2a26` |
| 字体 | PingFang SC；数字用等宽；正文 15px/1.7 |
| 动效 | 相机 800ms ease-in-out、面板 250ms；均尊重 `prefers-reduced-motion` |

### 3.6 关键交互（必须实现）

1. `recall` → 熊猫向节点射光束、节点闪、关联边粒子流动 + 对话上方 chip「🧠 想起了：感冒 · 西客松」。
2. `plan` → DAG 卫星从事务节点弹出（同 layer 同时亮），完成收拢，卡片/看板同步。
3. `memory` → 新节点从熊猫处飞出落位连边 + 提示「📝 记下了：攒钱 → 为了 → 换电脑」。
4. `action` → 事务详情里追加动作回执行 + 小提示（"已加 3 条提醒"）。
5. 打开页面 → 镜头环绕 + 扫描光扫过 + 晨报逐字出现，事务节点逐个点亮。
6. 事务看板点击 → 打开事务详情（含 DAG 回放、清单勾选、动作日志、关联记忆节点高亮）。

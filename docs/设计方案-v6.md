## 0. 诊断：为什么现在演不出来

| 讨论里定为「核心」 | 现状 |
|---|---|
| 大管家：替孩子**通盘**盯着所有事（8 万/月管家原型） | 只有一个对话框，你不说话它什么都不做 |
| 主动规划 + 实际执行 | 只有被问到才出一张卡片，没有后续跟进 |
| 知识图谱 / 树状图谱，反碎片孤岛 | 记忆本是一列文字 |
| 记忆是生长的（钢琴→小提琴、吉他） | 没有时间维度 |
| 持续理解（攒钱→换电脑） | 后端做了，界面看不出 |
| 家长—老师—孩子三方沟通（项目定位） | 完全没有 |
| 给孩子留点隐私 | 没有体现 |

**根因**：产品形态选成了"聊天机器人"，而团队要的是"管家"。聊天机器人的单位是**一问一答**，管家的单位是**一件件事务**——发现、规划、执行、跟进、结案，并且一直在后台盯着。

## 1. 新切入点：「事务驱动的主动管家」

**一句话**：PandaButler 不等孩子提问。它把孩子生活里的每件事都当成一个"事务"接管下来，从记忆图谱里发现事务、拆解执行、跟进到结案，并在孩子、家长、老师三方之间传话。

为什么选这个切入点：

1. **最能区分豆包。** 豆包是被动应答；管家打开就在汇报"我这几天替你盯着的 4 件事"。
2. **最好演示。** 评委不用会提问，打开页面就能看到管家在干活。讨论里说过"评委只会发一个问题"，这个切入点把这个风险消掉了。
3. **把所有功能串成一条线**：记忆图谱发现事务 → Agent 规划执行 → 家长确认 → 跟进结案 → 结果写回图谱。每个功能都有存在的理由，不再是零散的页面。

### 核心抽象：事务（Affair）

```
发现 ──► 规划 ──► 执行中 ──► 等确认 ──► 跟进 ──► 结案
 │        │         │          │          │        │
图谱/对话  DAG     工具+动作    家长端     提醒/巡检  写回图谱(done)
```

| 字段 | 示例（西客松） |
|---|---|
| title / kind | 西安西客松参赛 / 出行 |
| stage | 执行中 |
| due | 2026-10-18（倒计时 16 天） |
| owner_next | 管家 / 孩子 / 家长（当前该谁动） |
| linked_nodes | 西客松、感冒、机器人课、西安 |
| plan | DAG 节点 + 结果 |
| checklist | 学生证 ☑ 笔记本 ☐ 感冒药 ☐ … |
| actions | 提醒 3 条、车票待妈妈确认 |
| log | 时间线：谁在什么时候做了什么 |

小豆预置 4 件事务，覆盖四种形态：

| 事务 | 形态 | 展示的能力 |
|---|---|---|
| 🏆 西客松参赛 | 有截止日的出行 | Agent 规划、工具调用、执行动作 |
| 💻 换电脑计划 | 长期目标 | 持续理解（攒钱→换电脑）、进度条（已攒 / 目标） |
| 🤒 感冒康复 | 健康跟进 | 主动关怀、跨事务影响（提醒参赛带药） |
| 🎹 钢琴要不要再学 | 兴趣决策 | 记忆生长、引而不发、旧 dropped 节点复燃 |

## 2. 视觉形态：3D「熊猫管家的竹林小屋」

整个首页是一个 3D 场景，HUD 面板浮在场景上。不再是"一个对话框"。

```
┌──────────────────────────────────────────────────────────────────────┐
│ 🐼 PandaButler · 小豆的管家        今天 10/02 周五      [孩子|家长] 🔍 │
├───────────────┬──────────────────────────────────────┬───────────────┤
│ 📋 管家晨报    │                                      │ 💬 和管家说    │
│ 「小豆早！我   │        ✦  记忆星球（3D 图谱）  ✦        │               │
│  替你盯着 4 件 │     ·德·    ·智·    ·体·              │  对话流        │
│  事……」        │          ✦——✦——✦                    │  想起了 chip   │
│ ───────────   │    ·美·       ✦          ·劳·         │  DAG / 卡片    │
│ 🏆 西客松 16天 │                                      │               │
│   ▓▓▓▓░ 执行中 │      🐼（3D 低多边形熊猫管家）          │               │
│ 💻 换电脑 62%  │     站在竹林小屋前，抱着记事本           │               │
│ 🤒 感冒 跟进中 │                                      │  [chips]       │
│ 🎹 钢琴 待商量 │   ═══════ 时间轴 2024 ━━━━●━ 2026 ═══  │  [🤫][🎤][输入] │
└───────────────┴──────────────────────────────────────┴───────────────┘
```

### 2.1 记忆星球（3D 知识图谱），核心视觉

- **五大星区 = 德智体美劳。** 节点按领域聚成五团（力导向加领域引力），把讨论里一句带过的"德育体系"变成看得见的结构。领域与节点示例：
  - 智：机器人课、编程
  - 体：感冒、运动
  - 美：钢琴、画漫画
  - 劳：攒钱
  - 德：性格、家人、守约
- **节点编码**
  - 大小 = 提及次数。
  - 颜色 = 领域。
  - 亮度 = 新近度：旧记忆变暗，"记忆会生长"就看得见了。
  - dropped 节点显示为灰色虚影，done 节点带金环。
  - 悄悄话节点显示为锁形，家长视角下整体隐藏。
- **边**带关系文字（为了 / 联想到 / 导致 / 一起），关联正在发生时有粒子沿边流动。
- **事务即星座。** 每件事务是一个发光的大节点，连着它关联的记忆节点，点开就能看到"这件事管家依据了哪些记忆"。
- **交互**
  - 拖拽旋转、滚轮缩放。
  - 点节点，镜头飞过去，侧边抽屉显示时间线（每条事实带日期）和关联。
  - 底部时间轴：拖动或点 ▶ 播放，节点按 first_seen 依次亮起，钢琴在 2024 亮起、变灰，2026 又被重新点亮并连出新边。这是"兴趣演变"的展示。
- **和对话、执行联动**（最重要的"可见证据"）

  | 时机 | 星球上的效果 |
  |---|---|
  | 回复前（recall） | 熊猫射出光束连到被想起的节点，节点闪烁，关联边上流动粒子 |
  | 规划时（plan） | DAG 节点作为卫星从事务节点上弹出，按依赖连线，并行的同时发光，完成后收拢回事务节点 |
  | 回复后（memory） | 新节点从熊猫处飞出、落位、连边，伴随"📝 记下了"字幕 |
  | 打开页面（晨间巡检） | 镜头环绕一圈，扫描光扫过星球，事务节点逐个点亮，同时晨报逐字出现 |

### 2.2 3D 熊猫管家

- 用 three.js 基础几何体拼一只低多边形熊猫：头、耳、眼圈、身体、四肢，加领结和记事本作为管家道具。不需要建模软件和外部素材，没有版权问题。
- 状态动画：
  - idle：呼吸、眨眼
  - thinking：挠头，记事本翻页
  - working：低头写字，身边有工具图标环绕
  - happy：跳一下
  - worried：眉毛下垂
  - speaking：嘴部开合
- 点击熊猫会挥手，并说一句根据当前事务生成的话。
- 场景：一块地台、几根竹子、柔和的环境光和主光、地面阴影。只有几百个面，投屏用的笔记本也能跑满帧。

### 2.3 降级

- 检测到 WebGL 不可用或帧率低于 25 时，自动切换到 **2D SVG 版图谱**和现有的 SVG 熊猫。数据和交互不变，只是没有景深。
- three.js 和 3d-force-graph **放进 `web/vendor/` 本地托管**（仍然零构建，直接 ES Module 引入）。部署在自有服务器上，现场不依赖 CDN。

### 2.4 视觉语言

| 项 | 规范 |
|---|---|
| 主题 | 夜色竹林：深墨蓝背景 `#0f1a1f` → `#1c2b2a` 渐变，星球自发光 |
| 主色 | 竹青 `#4fbf7f` |
| 强调色 | 暖橙 `#ffb347`，只用于倒计时和需要行动的按钮 |
| 五领域色 | 德 `#ff8a80` · 智 `#64b5f6` · 体 `#81c784` · 美 `#ce93d8` · 劳 `#ffd54f` |
| HUD 面板 | 毛玻璃（`backdrop-filter: blur`），半透明深底，1px 亮边，圆角 18 |
| 字体 | PingFang SC；数字用等宽字体（倒计时、进度） |
| 动效 | 镜头过渡 800ms ease-in-out；面板 250ms；所有动画尊重 `prefers-reduced-motion` |
| 手机 | 3D 星球占上半屏（降低节点数），事务和对话做成可上拉的底部抽屉 |

**家长视角**：右上角切到「家长」后场景转为白天配色。星球隐藏悄悄话节点，左栏换成家长收件箱，右栏换成沟通翻译器。同一个场景、两种视角，"三方连接"一眼就能看懂。

## 3. 功能模块

### P0：必须做

| # | 模块 | 内容 |
|---|---|---|
| **A1** | 事务系统 | affairs.json + 状态机；对话或巡检中识别出新事务就创建；每件事务有阶段、截止日、清单、动作、日志；左栏看板，点开是事务详情页（详情页里含 DAG 回放） |

| **P1** | Agent 执行可视化 | DAG 卫星（3D）+ 对话流里的 2D DAG 卡片；节点可展开看工具、入参、返回摘要 |
| **P2** | 执行动作 | 加提醒、生成清单（勾选持久化）、请家长确认（车票、费用）、导出 .ics；全部写进事务日志 |

| **F2** | 悄悄话 | 🤫 标记的内容只进孩子档案，家长视角永远不显示，只提示"有 N 条悄悄话，管家替他保密" |
| **B1** | Bug | anthropic 流式请求 URL 拼成 `/v1/v1/messages`；流式请求不切换备用 Key |

### P1：P0 全绿后

| # | 模块 | 内容 |
|---|---|---|
| R1 | 成长雷达 | 德智体美劳五维评估，每维附证据节点，点一下镜头飞到对应星区 |
| R2 | 家长周报 | 本周事务进展、情绪曲线、兴趣变化、一条建议 |

### 不做

- 真实订票和支付：改为推给家长确认，并标注"参考信息，以官方为准"。
- 地铁 GPS、摄像头、汤姆猫式宠物、付费恢复记忆、定时任务式记忆。
- APP、手表、电子宠物：只作为路演 roadmap。
- 无法证实的投资背书。

## 4. 数据与后端

### 4.1 文件

```
data/child_xiaodou/
  graph.json        # 新：节点/边（领域、类型、状态、事实时间线、private）
  affairs.json      # 新：事务
  checklists.json   # 新
  parent_inbox.json # 新
  reminders.json    # 已有
  MEMORY.md / topics/ / daily/   # 保留：人可读，"数据即文件"的叙事
data/transport_db.json           # 新：威海→西安参考车次/航线（标注非实时）
```

graph.json 节点示例：

```json
{"id":"piano","label":"钢琴","domain":"美","type":"interest","status":"dropped",
 "first_seen":"2024-03","last_seen":"2026-10-02","weight":3,"private":false,
 "facts":[{"date":"2024-03","text":"学了三个月，坐不住放弃了"},
          {"date":"2026-10-02","text":"又说想学钢琴"}]}
```

小豆的图谱预置约 25 个节点、30 条边，时间跨度 2024→2026，日期与 race_db 一致。预置的是**用户数据**，不是答案，所有回复仍由 LLM 实时生成，符合红线。

### 4.2 Agent 流程

```
消息 ─► router(intent: chat | new_affair | affair_update | relay, mood)
      ─► retrieve：bigram 命中节点 + 沿边扩一跳 ──► recall 事件
      ├─ chat         ─► 流式回复（注入命中记忆）
      ├─ new_affair   ─► 建事务 ─► planner DAG ─► executor（工具+动作）─► synth 卡片
      ├─ affair_update─► 更新事务阶段/清单/日志（"我买好车票了"）
      └─ relay        ─► 传话筒（孩子 → 老师/家长）
      ─► extract（节点/边/事务变化）─► 原子写 ─► memory 事件
```

### 4.3 SSE 事件

`mode` · `recall` · `token` · `affair`（新建/阶段变化） · `plan` · `node` · `action` · `card` · `memory` · `done` · `error`

### 4.4 接口

```
GET  /api/briefing?name=               晨间巡检
GET  /api/graph?name=&view=child|parent
GET  /api/affairs?name=                GET/PATCH /api/affairs/{id}
POST /api/checklist/{id}               勾选
GET  /api/parent/inbox?name=           POST /api/parent/inbox/{id}
POST /api/relay                        {direction: teacher2parent | child2teacher, text}
GET  /api/ics/{affair_id}
GET  /api/logs                         已有：调用留痕，评委验真
P1: GET /api/growth · POST /api/report/weekly · POST /api/dream
```

## 6. 商业与 ROI

付费方仍是三层：2C 家长订阅、B2B2C 教培机构、2G 留守与特殊儿童公益。ROI 按机构学员服务岗测算，公式先定下来，**数字需团队核实后才能上 PPT**：

```
年节省/岗 = 服务家庭数 × 每户每周沟通工时 × 节省比例 × 52 × 时薪
示例假设：100 户 × 0.5h × 50% × 52 × 50 元 ≈ 6.5 万元/岗/年
```
